# Tailgate detector and relay

The standalone TinyScreen+ sketch is `SurveyFirmware/TailGateDetector/TailGateDetector.ino`. It uses a WiFi TinyShield, Wireling adapter and AMG88xx thermal camera on port 0–2, and the TinyScreen, Wireling, Adafruit AMG88xx/BusIO and WiFi101 libraries. It retains the legacy baseline, connected-blob and entry heuristics, display and plain HTTP `GET /?msg=...` protocol. This is independent of the survey app; no app UI integration is provided.

The firmware has no environment at runtime. Set the C preprocessor string macros `TAILGATE_WIFI_SSID`, `TAILGATE_WIFI_PASSWORD` and `TAILGATE_RELAY_HOST` in your **private build configuration**, e.g. use an Arduino CLI build property that adds quoted `-D` values. Do not commit those build settings; build flags can also be exposed in process lists and build logs. Empty defaults disable Wi-Fi; thermal detection continues. `RELAY_PORT` defaults to 8080. The host must be the relay computer's reachable LAN address, not localhost on the microcontroller. Network credentials become part of the firmware image; protect the device and image.

Run `python relay.py` from this directory. It listens on `127.0.0.1:8080` and accepts but does not forward messages by default. To allow a separate device to connect, explicitly set `TAILGATE_BIND` to a suitable private interface address (or `0.0.0.0` only on a trusted isolated network). `TAILGATE_PORT` changes the port. To enable Telegram forwarding, explicitly set `TAILGATE_FORWARD=1`, `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` in the process environment before launching. Without credentials it fails closed. Default mode returns 200 after accepting, not after delivery; enabled mode returns 200 only after the provider returns HTTP 200. It does not persist events or retry failures.

**Security:** device-to-relay HTTP has no authentication or encryption. Anyone able to reach it can inject alerts; a LAN bind is not safe on an untrusted network. Messages and Wi-Fi credentials need appropriate protection. Telegram receives message text when forwarding is enabled. The relay is single-threaded and not hardened for public exposure. The legacy folder is preserved unchanged and may contain historical credentials: handle it as sensitive and rotate any exposed credentials, including copies in history. No external message is sent by the offline tests.

**Detection limitations:** this is an approximate thermal heuristic, not identity or access control. Closely spaced people, large hot objects, stale baselines, lighting/thermal changes and mounting differences can cause false positives or missed tailgates. The device blocks during Wi-Fi connection, HTTP waits and recalibration. Hardware wiring, timing, sensor performance, actual notification delivery and board build require separate verification.

Offline tests: `python -m unittest discover -s App/Tools/TailGateRelay -p 'test_*.py' -v` from the repository root. The thermal test compiles the actual blob function with g++ if available; it is not a board build.
