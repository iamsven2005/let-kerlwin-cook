# SurveyFirmware

The canonical role folders are `roles/common`, `roles/hat`, and `roles/roomba`. Each is an Arduino-format library: main-firmware sources are under `src/`, while independent sketches are under `examples/`, outside the recursively compiled library source tree. To build the main sketch with Arduino CLI, install the board package and hardware libraries, then use `arduino-cli compile --fqbn <your-tinyscreen-fqbn> --libraries SurveyFirmware/roles SurveyFirmware` from the repository root. For Arduino IDE, make all three role libraries available in the sketchbook `libraries` directory (for example, directory links to the three canonical role folders), restart the IDE, then open `SurveyFirmware.ino`. If using copies instead, synchronize edits including mode and Wi-Fi settings to the installed copies before building. Select `HAT` (default) or `ROOMBA` by changing `SURVEY_MODE` in `roles/common/src/mode.h`; the sketch dispatches to the selected mode, and mode guards disable the other mode's implementation. Target: TinyScreen+; HAT requires TinyScreen, WiFi101 and Wireling libraries, plus its Wi-Fi, BMA250 and IR hardware. Set your own network profiles in `roles/common/src/wifi_logic.cpp`: network defaults are placeholders, not the original credentials. USB configuration and legacy UDP functionality remain as in the tracked glove project.

`roles/hat/src` contains the glove-specific features. The BMA250 and Wi-Fi drivers are in `roles/common/src`; both are currently enabled only in HAT mode. These files originate from `Legacy/GloveSurvey_Project/GloveSurvey`, with mode guards, updated include paths, and blanked network credentials. **HAT is a legacy glove implementation, not a validated head-mounted design.** IR obstacle reporting is gated by glove hand pose and uses hand-relative offsets; accelerometer step detection and calibration also assume wrist use. These can produce incorrect or missing obstacle/position data on a hat and must not be relied upon for navigation or safety. The accelerometer alone cannot measure heading; heading still requires manual correction. The legacy glove setup and protocol are described in `Legacy/GloveSurvey_Project/GloveSurvey/README_GLOVE.md` (its hardware placement assumptions apply to a glove, not a hat).

Additional standalone sketches:
- `roles/common/examples/TailGateDetector/`: thermal doorway-detection experiment; relay and security notes are in `App/Tools/TailGateRelay/`.
- `roles/common/examples/IRProximityDiagnostic/`: uncalibrated proximity and ambient-IR diagnostic; not a distance or safety sensor.
- `roles/roomba/examples/MotorController/`: the migrated motor-node algorithm and BLE peripheral. It defaults to simulation and cannot drive physical motors.
- `roles/roomba/examples/RobotReference/`: the older standalone Wi-Fi navigation and simulated odometry sketch, now also ported into ROOMBA mode.

`roles/roomba/src` runs the reference navigation, Wi-Fi command handling and telemetry with **forced virtual motors and odometry**. Its front IR defaults to the physical Wireling sensor; Wi-Fi readings likewise come from the Wi-Fi shield. Configure the initially blank ROOMBA Wi-Fi defaults in `roles/roomba/src/wifi_logic.cpp` or through its settings commands. Position telemetry retains its original format and is accompanied by a separate simulation message. Direct board-to-board communication, including a BLE central, has not been implemented. Do not infer that an existing motor controller is actively stopped; independently ensure motors are electrically disabled before testing.

HAT responds to `HELLO` and `FEATURES` with an `F` capability line. `MIRROR,ON` and `MIRROR,OFF` enable and disable periodic `D` debug pages; `SET,dbg_ms,<milliseconds>` sets the round interval (200–60000 ms). Pages show existing firmware state, not validated measurements. The legacy on-device debug pager is not implemented: `DEBUG` explicitly reports it unavailable. Existing HAT commands remain available.

Run the host-only checks with `bash SurveyFirmware/tests/run.sh` (g++ and Python 3 required). They compile both modes with Arduino stubs, exercise HAT capability and mirror commands and 4,000 loop iterations, and check ROOMBA RUN/PAUSE commands, virtual motion, and simulation labeling. They also run the standalone IR sketch and diagnostic, the MotorController simulation (excluding `UART.ino`), and RobotReference with a stubbed 4,000-loop harness and an Arduino-generated-prototype substitute. TailGateDetector's blob algorithm is tested separately by `python3 -m unittest discover -s App/Tools/TailGateRelay -p test_relay.py`; its full sketch is not stub-compiled. These are not board builds or hardware, Wi-Fi, sensor, or motor tests.
